# 乐乐代跑 · 产品方案设想报告

> 版本：V1.1 无支付双模式版（线下当面结算）
> 定位：校园场景的"互助中转"平台——⚡ 代跑互助 + 📚 二手书市，一个 App 两种模式。**平台不碰钱，只做撮合与信任。**

---

## 一、产品概述

**一句话定位**：帮同学之间像"顺路帮忙"一样解决日常需求——代跑腿（取快递、带饭、代跑腿）与闲置教材流转（二手书买卖）。平台负责撮合、时间管理、身份信任与爽约约束，**费用完全由双方线下见面后当面结算**。

**目标用户**：高校在校生（首批武汉大学）。
- 代跑挂单方：课多/懒得出门/时间冲突，愿意花小钱请同学帮忙
- 代跑接单方：课余时间充裕，顺路赚点零花钱的勤快同学
- 书市卖书方：学期结束的教材/资料闲置，扔了可惜
- 书市买书方：想低价收教材、求课程资料的同学

**解决的核心痛点**：
1. 快递驿站、食堂、办事窗口排队耗时，时间碎片化严重
2. 同学间帮忙缺乏"约定-履约"机制：说不清时间、怕被放鸽子、不好意思开口
3. 教材换代快、价格贵，二手书难找靠谱的校内渠道（校外平台邮寄贵、不信任、有抽成）
4. 现有平台（外卖/跑腿 App、校外二手平台）不覆盖校内场景，且抽成高、流程重

**产品原则**：
- **极简**：不碰支付、不做钱包，两种模式一键切换，流程 3 步以内完成一次互助
- **信任可视化**：实名学校 + 头像相认 + 爽约次数公示 + 互评
- **低运维**：规则全部自动化，无人工客服、无人工审核

## 二、核心业务流程

### 代跑 · 挂单方视角
```
选操场 → 填委托内容 → 填期望报酬（≥1.99 元/次，仅参考，不代收）→ 选周时间表时段（可拖拽连选）→ 设次数/性别要求 → 发布
→ 收到接单申请（确认 / 拒绝填原因 / 私聊）→ 确认后进入"进行中"
→ 按约定时间到操场集合（9点 = 8:55-9:00，迟到即爽约）→ 见面核对照片 → 交付委托物
→ 点"委托完成" → 线下当面结算费用 → 互相评价
```

### 代跑 · 接单方视角
```
浏览接单列表（筛操场/时间，可按金额高→低/低→高排序）→ 选日期申请（同时间点最多 5 单）→ 等挂单方确认
→ 按时赴约 → 到达打卡 → 完成委托 → 挂单方确认完成 → 收到评价
```

### 书市 · 卖书方视角
```
底部模式条切到"📚 二手书市" → 卖书：书名/课程/成色/期望价格/补充说明 → 可选拍一张封面照 → 发布
→ 收到"有人想买你的书"消息 → 进入书市消息会话议价、约时间地点 → 线下当面验书收款 → 标记"已售出"
```

### 书市 · 买书方视角
```
书市页搜索/按价格排序浏览 → 点进详情看封面与成色 → "联系卖家" → 会话议价
→ 平台提示线下当面验书付款，不代收不担保 → 交易完成
```

### 代跑关键规则（全部自动化）
| 规则 | 设计 |
|---|---|
| 期望报酬 | 挂单必填（每次 1.99-999.99 元），列表可"金额高→低 / 低→高"排序；仅作双方参考，平台不代收 |
| 集合时间 | 9 点格 = 8:55-9:00 集合，超过 9:00 视为爽约 |
| 挂单次数 | 默认 5 次，系统保证各次在不同日期；某天没人接自动顺延，次数用尽才结束 |
| 性别要求 | 挂单可设仅男/仅女，不符性别的用户自动不可见 |
| 爽约认定 | 集合后 15 分钟可发起；对方 12 小时内可反驳（订单终止、不计爽约）；逾期自动记入主页 |
| 雨天终止 | 任一方发起，对方 6 小时未回复默认同意终止 |
| 评价 | 完成后双方互评（星级+文字），展示在对方主页 |

### 书市规则（平台仅中转）
| 规则 | 设计 |
|---|---|
| 商品 | 书名（1-40 字）+ 课程（选填，用于搜教材）+ 成色（全新~使用痕迹 4 档）+ 价格（0.01-999.99 元）+ 说明 + 可选封面照一张 |
| 浏览 | 在售可见；自动隐藏自己与已封禁卖家的书；可按最新/价格排序，按书名/课程/说明搜索 |
| 联系 | 点"联系卖家"创建买卖私聊，卖家收到铃铛通知；会话长期保留（非代跑的临时会话） |
| 交易 | 平台明确提示：线下当面验书付款，平台不代收、不担保、无中间费用 |
| 状态 | 卖家可下架/重新上架/标记已售出；售出或下架后买家不可见、不可再联系 |
| 治理 | 买家可举报书籍（5-200 字原因），管理端审核结案；重复举报拦截 |

## 三、功能清单（当前已实现）

**客户端（Qt/QML，Android）**
- 邮箱验证码注册登录（无密码）；学校必选（仅可选择）；性别必填（提示部分挂单有性别要求）
- 底部模式条一键切换：⚡ 代跑互助 / 📚 二手书市（两种模式各自记忆上次停留页）
- 首次使用流程引导（双模式挂单/接单/当面交易全流程）
- *代跑模式*：接单 / 挂单 / 进行中 三个业务 Tab + 邀请 / 我的（共用）
  - 挂单：操场、委托内容、期望报酬（≥1.99 元/次）、周时间表选格（112 格，点按/拖拽连选）、次数、性别要求、我的挂单管理
  - 接单：列表筛选（操场/时间，条件本地持久化）、智能/金额排序切换、挂单详情（显示期望报酬）、用户主页
  - 进行中：多单并行、到达打卡、聊天（文字+位置，订单结束记录清除）、完成/爽约/雨天/反驳操作
- *书市模式*：书市 / 卖书 / 消息 三个业务 Tab + 邀请 / 我的（共用）
  - 书市：搜索、最新/价格排序、封面卡片列表、书详情（封面大图/成色/课程/卖家主页）、联系卖家、举报
  - 卖书：发布（书名/课程/成色/价格/说明/封面照上传）、我的书管理（查看/下架/重上架/已售出/换封面/未读角标）
  - 消息：买卖会话列表（书状态标签、未读数）、卖家-买家长期私聊（文字+位置，含"线下当面交易"系统提示）
- 邀请：邀请码 + 好友关系（无经济奖励）
- 我的：头像（≤200KB，用于相认）、数据统计（完成/爽约）、历史记录、公告中心、使用指南、检查更新（应用内下载安装）、退出登录

**服务端（Node.js）**
- 邮箱验证码（QQ 邮箱 SMTP）、JWT、限流防刷
- 订单状态机全自动化（申请超时关闭/雨天默认同意/爽约自动认定/次数耗尽自动结束）
- 书市接口：发布/浏览（含学校过滤与价格排序）/我的书/详情/封面上传（按书籍 ID 存储一张）/联系（建会话+系统提示）/状态机/举报；买卖私聊独立会话与未读计数，事件推送独立于代跑
- 实时推送（WebSocket）
- 管理后台：学校/操场管理、公告、用户管理（封禁）、举报处理、书市书籍管理（搜/下架/已售出/举报标记）、书市举报结案、规则参数、版本发布

## 四、迭代记录与后续规划

### ✅ V1.1（本次版本）——双模式 + 期望金额
1. **期望报酬替代固定 1.99**：挂单界面可输入期望金额（注明不低于 1.99 元/次），详情/聊天/进行中/历史均展示；接单列表新增"金额高→低 / 低→高"排序
2. **二手书市模式**：一个 App 两种模式，底部模式条一键切换；平台仅做联系中转，无费用经手（线下当面验书付款），无平台担保
3. **界面统一美化**：书市沿用代跑的卡片/渐变/弹层体系，首屏引导与使用指南同步更新

### ✅ V1.0（上一版）已优化
1. **流程极简化**：删除全部支付环节（充值/余额/提现/抽成/邀请奖励），确认接单即进入进行中
2. **线下结算明确化**：首次引导与使用指南明确"见面当面结算"，无任何线上资金概念
3. **界面美化**：品牌渐变主色、卡片阴影与按压反馈、TabBar 选中动效、渐变头部
4. **信任机制强化**：完成互评展示在主页、爽约次数三方公示、到达打卡

## 五、运营建议

1. **冷启动**：先拉 3-5 个班级群试运营；教材季（开学/期末）主推书市；邀请码互相绑定形成口碑
2. **信任冷启动**：运营初期管理端人工核验头像真实性；公告鼓励"先小额委托（取快递）再大额"
3. **爽约治理**：爽约次数公示是核心约束；连续爽约可手动封禁
4. **举报机制**：辱骂/骚扰、售假劣质书走举报 → 封禁闭环，无需客服
5. **内容治理**：委托内容自动过滤联系方式（微信号/手机号），防止脱离平台私下交易（安全考虑）

## 六、风险与合规

| 风险 | 应对 |
|---|---|
| 线下交易纠纷（费用/物品损坏/书况不符） | 平台明确"不介入金钱、不做担保"，靠互评与爽约公示约束；书市鼓励当面验书，描述不符可走举报 |
| 身份冒用 | 学校实名 + 见面核对照片；建议后续接入学生认证（学号+验证码） |
| 低配服务器 | 已选型零依赖 Node+SQLite，1G 内存可跑；头像/书封压缩 200KB 内；无图片聊天 |
| 网络安全 | 当前 HTTP 明文，**上线前务必绑定域名 + HTTPS** |
| 隐私 | 仅展示昵称/性别/学校/统计，不展示手机号等联系方式 |

## 八、技术架构摘要

```
Android 客户端（Qt 6 QML + C++，CMake）
    │  HTTPS/REST + WebSocket
    ▼
Node.js 服务端（Express + node:sqlite + ws）
    ├─ 业务路由：auth / orders / active / chats / books / book-chats / invite / notices / reports / admin
    ├─ 自动任务：申请过期、雨天默认同意、爽约自动认定、订单收尾
    └─ 管理后台（静态网页）：学校/操场/公告/用户/举报/书市书籍/书市举报/规则/版本
数据库：SQLite 单文件（WAL），备份脚本自动每日备份
文件存储：uploads/avatars（头像）、uploads/books（书封，按书籍 ID 一张）、uploads/apk
```
