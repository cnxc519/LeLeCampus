## 🔧 需要你操作（按顺序）

1. **部署服务器（一键）**：在本地电脑执行
   ```bash
   cd server && bash deploy.sh
   ```
   脚本自动：上传代码 → 装 Node 24 → 装依赖 → PM2 启动 → 放行 8899 端口（会提示输入服务器 SSH 密码）
2. **阿里云安全组**：网页控制台放行 TCP 8899 端口
3. **修改 config.json**（`ssh root@47.91.25.15` 后编辑 `/opt/lele/server/config.json`）：
   - `dev_mode` 改 false、`jwt_secret` 改随机串、`admin.password` 改掉
   - 然后 `pm2 restart lele`
4. **本机装 Qt + Android SDK**（参考 docs/APP_BUILD.md），构建 APK 装手机验证
5. **发布版本**：构建 Release APK → 管理后台"版本更新"上传 → 设置版本号（与 `app/src/main.cpp` 的 APP_VERSION_CODE 一致）
6. **验证码邮件**：config.json 已内置 QQ 邮箱 SMTP，部署后发一次验证码测试收信
7. **上线前安全建议**：绑定域名 + HTTPS（当前 http 明文传输验证码）

## 📋 设计决策说明（我替你定的，可改）

1. **无支付模式**：平台不碰钱，无充值/余额/提现/抽成/邀请奖励；确认接单即进入进行中，费用线下见面后当面结算（产品方案见 docs/PRODUCT_PLAN.md）
2. **双模式（一个 App）**：底部模式条一键切换 ⚡代跑互助 / 📚二手书市；代跑三 Tab（接单/挂单/进行中）、书市三 Tab（书市/卖书/消息），邀请/我的共用，各模式记忆上次停留页。书市纯线下交易：平台只做联系中转，不代收钱、不做担保，商品详情/会话里明确提示当面验书付款
3. **爽约机制（全自助，无平台审核）**：
   - 集合后 15 分钟才能发起爽约认定（防止提前乱点）
   - 被认定方 12 小时内可**反驳** → 订单终止（不计爽约、不判定责任），双方自行协商
   - 逾期未反驳 → 自动记入爽约次数（主页展示）
   - 到达打卡（双方可用）作为证据
4. **挂单次数 = 天数，顺移保次数**：周时间表决定每周哪几天几点，次数 N = 做 N 天（系统保证不同日期）。某天没人接自动顺延到后续匹配日期，直到完成 N 次挂单才结束
5. **期望报酬（代跑）**：挂单必填、每次 1.99-999.99 元（低于 1.99 拒收）；展示在列表/详情/聊天/进行中/历史，金额仅作双方参考，平台永不代收
6. **雨天终止**：任一方发起，对方 6 小时未回复默认同意终止，无费用
7. **私聊记录**：代跑订单结束后自动删除消息记录（"临时性质"）；书市会话长期保留（书不过期，买前反复聊很正常）
8. **排序**：接单默认"智能"（可接格子多的在前 → 今明无时间/被接完的靠后 → 其余随机）；可切"金额 高→低 / 低→高"（同价回落智能次要因子）；筛选条件保存在手机上，直到用户自己改。书市默认最新发布，可切价格升降序
9. **评价**：完成后双方各可评价一次（星级+文字），展示在对方主页
10. **更新方式**：应用内下载 APK → 系统安装界面；强制更新不可跳过；失败可浏览器下载
11. **无人工客服、无平台审核**：纠纷全部自助，仅保留举报（治理性质）供管理端封禁

## 🐛 已知边界（低配服务器取舍）

- 聊天不支持图片；头像每人一张 ≤200KB（自动压缩）；书封每本一张 ≤200KB（重新上传即覆盖，以书籍 ID 命名存储）
- 书市暂无求购/收藏（当前为浏览-联系-当面交易的极简闭环）
- 通知仅 App 在线时实时推送，离线消息登录后拉取；无系统级推送
- 服务端无 HTTPS；强烈建议上线前做
- 应用内安装依赖 androidx.core（Qt 默认模板可能缺，报错时在 build.gradle 加 `implementation 'androidx.core:core:1.13.1'`）
